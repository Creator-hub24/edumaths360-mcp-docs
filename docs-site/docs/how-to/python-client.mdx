# Connect from a Python client

You do not need an AI app to use an MCP server. This guide shows how to call the Edumaths360 server from your own Python code, for example in a test, a script or a backend service.

**Before you start:** run `uv sync --extra dev` in `server/`.

## Key points

### Launching the server

`StdioServerParameters(command=..., args=[...])` tells the client how to start the server as a subprocess. The client owns the process: it starts when you enter `async with Client(...)` and stops when the block ends.

### Reading results

Every `call_tool` result has:

| Attribute | Contains |
| --- | --- |
| `structured_content` | The JSON object that matches the tool's `outputSchema`. Use this in code. |
| `content` | A list of content blocks (usually text) intended for the AI model. |
| `is_error` | `True` when the tool reported an error, such as invalid input. |

### Two kinds of error

1. **Tool errors** come back as a normal result with `is_error=True`, as in step 5 of the client. Bad arguments and "topic not offered" errors work this way, so a model can read the message and correct itself.
2. **Protocol errors** raise an `MCPError` exception in the client. For example, reading `syllabus://grade/12` fails with JSON-RPC error code `-32602`. See the [error reference](../reference/tools.md#errors).

```python
from mcp import MCPError

try:
    await client.read_resource("syllabus://grade/12")
except MCPError as exc:
    print(exc.error.code, exc.error.message)
    # -32602 No syllabus for grade '12'. Use a grade from 6 to 10.
```

### Testing in-process

For unit tests you can skip the subprocess and pass the server object straight to the client. The test suite does this in `server/tests/test_server.py`:

```python
from mcp import Client
from edumaths360_mcp.server import mcp

async with Client(mcp) as client:
    result = await client.call_tool("generate_problem", {"topic": "fractions", "grade": 7})
```

This runs the full MCP message exchange in memory, which is fast and needs no process management.

### Protocol version

The SDK client negotiates the newest protocol version both sides support. With SDK 2.x on both sides, that is `2026-07-28`, as the first line of the output shows. Hosts that use the older `initialize` handshake get `2025-11-25`, as shown in the [JSON-RPC examples](../reference/json-rpc-examples.mdx).
